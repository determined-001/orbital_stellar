# worker-core Changelog

## [Unreleased]

### Added
- **Subscription model and subscriber webhooks** (`subscription/`) - `SubscriptionService` over a `SubscriptionStore` (`MemorySubscriptionStore` in-repo), with `create`/`pause`/`resume`/`cancel`/`changeTier`, an append-only audit trail, and cancellation effective within one window rather than retroactively. A subscription carries no key, allowance, delegated signer or spending limit; `test/subscription/noAuthority.test-d.ts` fails the build if one is added.
- **Backstop latency tiers** (`backstop/tiers.ts`, `backstop/index.ts`) - `TIERS` with `latencyBoundMs`, `gracePeriodMs`, `pricePerWindowStroops` and a machine-readable `guaranteedWhen` (so 21.4's SLO monitoring asserts against the same numbers a subscriber was sold), plus `withinGuarantee`/`guaranteeDeadline` from that one source. Only `time-insensitive` is registrable; registering `latency-sensitive` fails with `TIER_NOT_REGISTRABLE` naming 22.4. The tier is attached to the subscription and **versioned** - a tier change is a new version, lifecycle transitions are not. `latency-sensitive`'s registrability is derived from 22.4's existing `LATENCY_SENSITIVE_TIER_DEFAULT` rather than a second boolean, so the safety switch cannot be flipped in one place and contradicted in another. See `docs/workers/tiers.md`.
- **Event-based trigger class** (`triggers/eventTrigger.ts`, `triggers/predicate.ts`) - the second §C.1 trigger class: a condition is a declarative predicate over `NormalizedEvent`, compiled once at registration by `compileEventCondition` and built on `pulse-core`'s existing filter and guard helpers rather than a new matching language. `EventTriggerPlanner.plan()` turns a stream of events into ordered `FireDecision` windows and is pure - no clock, no network, no state outside its arguments - so the same ledger range always yields the same decisions, which is what lets 19.1 say "should have fired" about a range it replays later. Duplicate source events (re-delivery, or a ledger re-scanned after a reorg) resolve to the same window via `eventIdentity`, and firing defers to 18.6's claim protocol: `ClaimStoreFireClaims` adapts the shipped `ClaimStore` onto this module's narrower `FireClaimStore` port, so an event trigger and a time trigger contend for one claim instead of two that can disagree. Trade-signal conditions are rejected at registration with `TRADE_SIGNAL_REJECTION`, pointing at W4 and the vault pattern - a gate, not a warning.
- Initial package scaffold. `WorkerDefinition`, the `Trigger` discriminated union (`time` | `event` | `computation`), `Schedule` (`interval` | `cron`, both with an explicit `timezone`), and `assertImplementedTrigger`/`TriggerNotImplementedError` for the runtime W0 rejection of the `event` and `computation` trigger kinds. `0.x` - may break in minors per `STABILITY.md`.
- **Latency-sensitive tier stub** (`hotPath/`, `backstop/tiers.ts`) - not a working hot path; see the README's "Latency-sensitive tier" section. `HotPathPlan` (`StaticHotPathPlan | DynamicHotPathPlan`) makes the pre-signing safety boundary structural rather than a per-call judgment call (`isPreSignable`); `LatencyScorecardEntry`/`recordScorecardEntry` is the "measured end to end, published on the scorecards" shape; `TierEnableDecision`/`LATENCY_SENSITIVE_TIER_DEFAULT`/`assertTierEnableDecisionIsValid` require a documented, reversible enable decision backed by a `CostMeasurement`, shipped disabled. `assertHotPathReady` throws unconditionally - #1064 (21.3) and #1070 (22.3), and a real submitter, do not exist yet.
- **Copy-trade worker decision logic** (`workers/copyTrade.ts`, `vault/`) - not runnable against a real vault yet; see the README's "Copy-trade worker on the vault pattern" section. `VaultClient` specifies the constrained-function boundary a real vault client must satisfy (`UNIMPLEMENTED_VAULT_CLIENT` throws from every method - 22.1's vault contract does not exist yet). `planCopyTrade` mirrors an observed trade through a `VaultClient`, bounded by `computeMirroredSize`'s position-sizing cap, subscriber revocation, and a ledger-based latency budget, producing either an executed outcome or a named, recorded `CopyTradeSkipReason` - never a silent drop. `createCopyTradeTrigger` reuses the existing `EventTrigger` type rather than adding a second matching path.
- **Price and slippage guard rails** (`guards/priceGuard.ts`, `guards/circuitBreaker.ts`) - `checkStaleness`, `checkDeviation`, and `checkPriceGuard` for fixed-point, dual-source price validation before a worker acts on a reading; `CircuitBreaker` for halting a worker after N consecutive guard trips, requiring a documented manual re-enable. On-chain enforcement (the vault side of the split) is specified but not implemented - see `docs/design/worker-guard-rails.md`; it depends on the vault contract from 22.3, which does not exist in this repo yet.
