# Migrating from 0.1.0 to 1.0.0

This guide is the procedural companion to the `v1.0.0` release notes. It lists
every breaking change with a before/after edit, calls out source-compatible
surfaces as **nothing to do**, and covers the Wave 8 / Wave 1.2 registry
configuration surface.

**Do not treat this as a second changelog.** Narrative Added / Changed /
Fixed / Security / Impact text lives in [`CHANGELOG.md`](../../CHANGELOG.md)
(the `[1.0.0]` entry cut by issue 9.6) and rolls up from per-package
changelogs such as
[`packages/pulse-core/CHANGELOG.md`](../../packages/pulse-core/CHANGELOG.md).
Until `[1.0.0]` is published, the breaking items below match that package’s
`[Unreleased]` section — link there rather than copy its prose.

Stability policy from `v1.0.0` onward:
[`STABILITY.md`](../../STABILITY.md).

## Breaking changes

### 1. Default `abiRegistry` is active

**Before (`0.1.0`)** — omitting `abiRegistry` meant no lookup and synchronous
`contract.emitted` delivery:

```ts
import { EventEngine } from "@orbital-stellar/pulse-core";

const engine = new EventEngine({
  network: "mainnet",
  soroban: { rpcUrl: "https://mainnet.sorobanrpc.com" },
  // abiRegistry omitted → decodedData always undefined, sync delivery
});

engine.subscribeContract("app", {
  filters: [{ contractIds: ["CCW67…"] }],
}).on("contract.emitted", (event) => {
  // event.decodedData === undefined
});
```

**After (`1.0.0`)** — omitting `abiRegistry` resolves the default chain
(`createDefaultAbiRegistryClient`): bundled well-known specs (USDC, EURC,
AQUA, native XLM wrapper), and the on-chain registry once deployed.
`decodedData` populates automatically for those contracts. Delivery is
**always asynchronous** (microtask through registry lookup), including for
unknown contracts.

```ts
import { EventEngine } from "@orbital-stellar/pulse-core";

const engine = new EventEngine({
  network: "mainnet",
  soroban: { rpcUrl: "https://mainnet.sorobanrpc.com" },
  // abiRegistry omitted → default chain; well-known contracts decode
});

engine.subscribeContract("app", {
  filters: [{ contractIds: ["CCW67TSZV3SSS2HXMBQ5JFGCKJNXKZM7UQUWUZPUTHXSTZLEO7SJMI75"] }],
}).on("contract.emitted", (event) => {
  // event.decodedData may be a DecodedEvent for well-known contracts
});
```

**Opt out** — preserve exact `0.1.0` behavior:

```ts
const engine = new EventEngine({
  network: "mainnet",
  soroban: { rpcUrl: "https://mainnet.sorobanrpc.com" },
  abiRegistry: false, // sync delivery; decodedData always undefined
});
```

### 2. `decodedData` is the decoded payload, not the raw ABI spec

**Before (buggy `0.1.0` consumers)** — some paths set `decodedData` to the
looked-up spec / raw XDR entries:

```ts
watcher.on("contract.emitted", (event) => {
  const specOrPayload = event.decodedData;
  // might be a ContractSpec / entries blob — not the event payload
});
```

**After (`1.0.0`)** — `decodedData` is the result of `decodeContractEvent`
(`DecodedEvent`: `functionName`, `topics`, `data`), or undefined on miss /
decode error:

```ts
import type { DecodedEvent } from "@orbital-stellar/abi-registry";

watcher.on("contract.emitted", (event) => {
  const decoded = event.decodedData as DecodedEvent | undefined;
  if (!decoded) return;
  console.log(decoded.functionName, decoded.topics, decoded.data);
});
```

If your code inspected `decodedData.entries` or treated it as a spec object,
update those readers to the `DecodedEvent` shape.

## Source-compatible — nothing to do

These surfaces keep working without edits when you bump to `1.0.0`:

| Area | Why |
|---|---|
| Classic Horizon `subscribe(address)` + classic `NormalizedEvent` types | Unchanged taxonomy and routing |
| `Watcher` `on(type)` / `on("*")` / `filter` | Same pub/sub contract |
| Cursor stores (`Memory` / `File` / `Postgres` / `Redis` / `S3`) | Opt-in; key format unchanged |
| Webhook delivery + HMAC headers | Wire contract covered by `STABILITY.md`; no rename |
| `pulse-notify` hooks already on `0.1.0` APIs | Additive event types only — keep a `default` branch |
| Multi-network `network: NetworkSourceConfig[]` | Additive optional field on events |
| Explicit custom `abiRegistry` client you already passed | Still honored; default chain only applies when omitted |
| `abiRegistry: false` | Explicit opt-out of the new default |

**Nothing to do** means: bump the package version and leave that call site
alone. New optional fields (`decodedData` when you never read it, new
`contract.*` / lifecycle notification variants) should be ignored via
`default` in exhaustive switches per
[`STABILITY.md`](../../STABILITY.md).

## Registry configuration (Wave 8 / Wave 1.2)

Wave 8 is the deploy-and-wire wave for the on-chain registry (issues 8.1–8.8).
The **client configuration surface** consumers touch is `CoreConfig.abiRegistry`
plus `createDefaultAbiRegistryClient`.

### Default chain (omit `abiRegistry`)

```ts
import { EventEngine } from "@orbital-stellar/pulse-core";

new EventEngine({
  network: "testnet",
  soroban: { rpcUrl: "https://soroban-testnet.stellar.org" },
  // uses createDefaultAbiRegistryClient() internally
});
```

Precedence inside the default client:

1. SEP-48 embedded specs — when you build the client with `rpcUrl`
2. Bundled well-known specs — offline
3. Hosted registry — when `ORBITAL_HOSTED_REGISTRY_BASE_URL` (env or constant)
   is non-empty and `chainOnly` is not set. Falls through to the chain link on
   timeout, 5xx, or a sampled spec-hash mismatch, so an outage there never
   blocks resolution
4. On-chain registry — when `ORBITAL_REGISTRY_TESTNET_CONTRACT_ID` (env or
   constant) is non-empty

### Explicit hosted / local / chained clients

```ts
import { EventEngine } from "@orbital-stellar/pulse-core";
import {
  AbiRegistryClient,
  LocalAbiRegistryClient,
  ChainedAbiRegistryClient,
  createDefaultAbiRegistryClient,
} from "@orbital-stellar/abi-registry";

// Hosted only
new EventEngine({
  network: "mainnet",
  soroban: { rpcUrl: "https://mainnet.sorobanrpc.com" },
  abiRegistry: new AbiRegistryClient({ baseUrl: "https://abi.example.com" }),
});

// Compose SEP-48 + well-known + on-chain yourself
new EventEngine({
  network: "testnet",
  soroban: { rpcUrl: "https://soroban-testnet.stellar.org" },
  abiRegistry: createDefaultAbiRegistryClient({
    rpcUrl: "https://soroban-testnet.stellar.org",
  }),
});

// Filesystem offline
new EventEngine({
  network: "testnet",
  abiRegistry: new LocalAbiRegistryClient({
    specsDir: "./specs",
  }),
});
```

### Environment variables (Wave 8 deploy)

| Variable | Role |
|---|---|
| `ORBITAL_HOSTED_REGISTRY_BASE_URL` | Hosted registry base URL; empty disables the hosted link entirely |
| `ORBITAL_REGISTRY_TESTNET_CONTRACT_ID` | On-chain registry contract ID; empty until 8.1 deploy |
| `ORBITAL_REGISTRY_PUBLISHER_ADDRESS` | Publisher filter for on-chain lookups |
| `ORBITAL_REGISTRY_TESTNET_RPC_URL` | Defaults to `https://soroban-testnet.stellar.org` |

Until those IDs are published, the default chain still decodes **bundled
well-known** contracts with zero env configuration.

More detail:
[`apps/web/content/guides/abi-registry.md`](../../apps/web/content/guides/abi-registry.md),
[`packages/abi-registry/README.md`](../../packages/abi-registry/README.md).

## Checklist

1. Read [`CHANGELOG.md`](../../CHANGELOG.md) `[1.0.0]` (or
   `packages/pulse-core/CHANGELOG.md` `[Unreleased]` until the cut).
2. Decide: keep the new default registry, pass a custom client, or set
   `abiRegistry: false`.
3. Audit any code that read `decodedData` as a spec object — switch to
   `DecodedEvent`.
4. Ensure `switch (event.type)` has a `default` that ignores unknown variants.
5. Bump `@orbital-stellar/*` packages together to `1.0.0` so inter-package
   ranges stay consistent.
